## 阶段三验收矩阵

| 场景 | 实际验证 |
| --- | --- |
| 实际空间而非稀疏长度 | `max_result_bytes=384` 的 slot 在返回意图前长度和 `st_blocks * 512` 均为 4096；header 绑定原 ExecutionBinding，权限 0600。 |
| 配额 | 全局逻辑、逐 owner 逻辑、全局物理、逐 owner 物理分别阻塞队首；完整、未 ACK、已 ACK 等待保留期都不释放预留。 |
| 真实 HTTP 与结果 | Loopback chunked HTTP 的逐字节 UTF-8、多 delta、空文本有 IDs、重复 token、末批 token + terminal，以及正常零输出均完整保存；usage 与摘要绑定。 |
| 完整性门槛 | Terminal → STREAM_FINISHED(COMPLETE_PROTOCOL) → RESULT_DURABLE 顺序成立；缺 usage/DONE 仍 Pending，不发布完整结果。 |
| 下游停止消费 | 两个结果占满 8192 物理字节后第三请求未 POST；年龄再大仍不清理；ACK+保留期清理后只派发第三个原未派发执行。 |
| Allocate ENOSPC | 本地分配故障注入时服务器零 POST、execution 仍 UNSENT；孤立文件经 reconcile 删除，恢复后才首次提交。 |
| 输出越界/写失败 | 不越过预留、不静默截断，不发布 durable result；停派且 journal 可写时继续收集原 stream 的 terminal/usage/EOF，下一请求未提交。 |
| 文件 sync 失败 | Header sync 失败不产生意图；delta sync 失败不允许后续派发且保留执行责任；footer sync 失败不能发布 RESULT_DURABLE。 |
| 进度 journal 提交失败 | 文件已有文本，但已提交 token 数仍零、gate 仍 CLOSED；handle poisoned，重开 UNKNOWN；超出旧 checkpoint 的尾部不成为已提交证据。 |
| 意图提交失败 | 已分配文件没有对应 intent，重开会回收 orphan，不把它当作已提交请求。 |
| 文件完整而 durable action 未提交 | 子进程写入并同步 footer，故意失败 RESULT_DURABLE 提交，然后 `process::exit(91)` 不执行析构；重开从已提交前缀与完整协议摘要恢复，只有一个 intent 和一个 RESULT_DURABLE。 |
| ACK 丢失与失败 | 独立 mock sink 同步后丢 ACK，重开仍可读取原结果；ACK journal 失败仍保留文件与额度，重放同一 receipt 后才交接。 |
| Owner/digest/receipt | 错 owner/摘要拒绝；receipt 冲突拒绝；重复 ACK 不追加事件、不延长 deadline；时钟/保留期溢出拒绝。 |
| 清理故障窗口 | 删除前失败、unlink 后目录 sync 失败、unlink 后 ResultCleaned 提交失败都保留 quota；重开从 cleanup intent 完成，一次释放。 |
| 文件丢失/损坏 | 重开或 ACK 前校验失败会记录 Unavailable 和 Recovery，保留 quota；显式核对、丢失声明/清理后才能恢复。 |
| 无效/重复 delta | 同序号同 token 但不同文本为冲突；已完成后的非法新观察不改文件；重复 token 内容不去重。 |
| 不能绕过恢复 | Metadata-only 打开启用过 spool 的 journal 不能激活；policy 变化拒绝；缺 binding/root 或旧 spool 无匹配 journal policy 拒绝自动接管。 |
| UNKNOWN 的边界 | 未决执行不能通过丢弃结果释放执行责任；必须取得真实 terminal 或显式旧 epoch 隔离证据。 |
| 兼容与外部边界 | 阶段一 frozen journal 和阶段二独立重建 fixture 均能重放；旧协议完整结果仍 Pending，不能捏造缺失文件。事件不含输出文本/IDs，不增加金融动作。 |

ENOSPC、写入和 sync 的错误通过本地 `SpoolFaults` 注入，SQLite 故障通过事务 trigger 注入；没有填满主机磁盘，也没有模拟物理设备掉电。实际文件预分配、sync 调用与进程退出恢复另有真实执行证据。

## 验收边界

- 已接受本地单进程组件、磁盘文件、loopback mock HTTP 与独立 mock sink 的完整流程；未部署或推送远端。
- 仅实际执行 macOS/APFS 后端。Linux 预分配代码存在，但本次未运行；其他 OS/不兼容文件系统分配粒度拒绝派发。
- `owner_ref` 检查不是认证，sink receipt 是可信适配器声明；阶段四先验证真实 vLLM，阶段五再讨论并接入 BitRouter 的认证、owner、事件/结果接口、持久化 ACK 与服务端时钟。
- 物理 quota 仅包括 slot 数据，不包括 journal/WAL、文件系统元数据、快照、sink。未做 journal 历史归档；需要独立磁盘余量和告警集成。
- 未 ACK 的完整结果不会自动过期删除。已终止但不完整/不可用的结果只能经有证据的显式关闭/丢弃；不等于没有执行，也不产生退款或收费。
- 文件 sync、SQLite FULL 与 hash chain 不替代硬件耐久性、整体快照防回滚或状态新鲜度；runbook 所需真实 writer/engine 隔离不由这些 Rust API 自动完成。
- 未实际运行 tokenizer 空间上界校准、vLLM/GPU/TEE、吞吐/TTFT 或缓存收益测试。后续阶段仍须验证这些条件；本报告不称生产就绪。
