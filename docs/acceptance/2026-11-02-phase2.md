## 阶段二验收矩阵

| 场景 | 已验证结果 |
| --- | --- |
| 分片/粘包 | 同一 SSE 流的每个字节切分位置解出相同事件；实际 HTTP chunked 逐字节发送含中文 UTF-8 的响应也通过。 |
| SSE 语法 | BOM、CRLF/LF/CR、注释、多行 data、id/retry 处理符合本 profile；不实现 EventSource reconnect。 |
| 数据上限 | 原始行、完整事件、整个流分别有界；后续错误不会丢弃同一 read 中已经完整解出的前缀事件。 |
| 请求映射 | 原 token IDs、max tokens、namespace、整数 sampler 的数值映射、echo/truncation/n/return_token_ids 设置正确；无 bid/budget/付款/hold 字段。 |
| 响应身份 | 错 ID、choice、prompt IDs、词表 token、错误 finish_reason、重复已知 JSON 字段和整事件 usage 不一致不能打开 gate。 |
| 非进度消息 | Heartbeat、空文本/空 token IDs、prompt IDs、metadata、usage-only 与单独 DONE 不能充当生成进度或终止证明。 |
| 同事件错误优先级 | 同一个事件即使携带生成 IDs，只要根错误、错误原因或 usage 无效，就不先发布进度/终止。 |
| 实际请求重叠 | A 发出进度后仍被 mock 屏障阻塞；B 可以发起并完成。测试等待 B 的 durable terminal 事件后才允许 A 终止，不依赖猜测性 sleep 判断完成顺序。 |
| 请求/连接背压 | 执行在途数和仍存活的 HTTP stream 数分别受限；即使 gate 或执行预算已释放，也不能越过 live-stream 上限。 |
| 超时 | HTTP headers 等待、无首进度但持续 heartbeat、进度后空闲、持续 heartbeat 但超过总时限，分别触发明确 timeout；UNKNOWN 仍保留预算。 |
| 禁止重试/redirect | 302、400、429、500、502、503 和断连每个 execution 都只发一次请求；redirect 目标收到零请求，恢复前再次运行被拒绝。 |
| 终止前断流 | UNKNOWN 停派，保留已有进度 gate、执行身份与在途预算。 |
| 终止后断流/格式错误 | 保留 terminal 与 gate、释放执行预算，但摘要为 INCOMPLETE_PROTOCOL，不谎称完整结果。 |
| 缺 usage 或 DONE | 正常终止事实保留；协议摘要明确缺失项，不能按零 usage 或普通 EOF 补成成功。 |
| Journal 写失败 | 意图未提交时服务器收到零 POST；进度提交失败时只有 A 收到一次 POST，B 未提交。handle 被 poisoned，重开仍要求核对。 |
| Runner 取消 | 中断 guard 持久化停派并把尚无终止证据的执行标成 UNKNOWN；不会由下一次 run 重发。 |
| 摘要幂等/持久化 | 相同摘要重复确认不增事件；冲突锁存完整性故障；正常摘要可在重开后读取与重放。 |
| 阶段一兼容 | 从旧提交独立构建并生成 journal，导入其原始 metadata/action/event 行；新代码成功 replay、进入恢复，再接收新计划与 mock HTTP 事件。 |

阶段二没有模拟 GPU 执行崩溃。进程级意图前/后退出的回归来自阶段一；阶段二另外验证取消和真实 HTTP 路径上的持久化失败窗口。

## 实际 walkthrough 结果

[保存的 JSON](phase2-mock-output.json) 来自示例实际运行：

```text
HTTP POST 顺序：exec-1-1 → exec-1-2 → exec-2-1
HTTP POST 总数：3
B terminal 早于 A terminal：true
三个协议摘要：COMPLETE_PROTOCOL
snapshot 与 replay：一致
重开：RECOVERY_REQUIRED
重开后额外 POST：0
```

最终在途/context 预算为零，逻辑 spool 预留仍为 1152 字节。A 的首进度消息只有 token IDs 而无可见文本，仍正确打开门。B、C 响应包含三字节 UTF-8 文本。本文不据此报告真实模型 TTFT、吞吐或缓存收益。

## 验收边界

- 仅接受 loopback mock HTTP；没有远端 HTTPS、真实 vLLM、GPU、BitRouter 或 TEE 部署验收。
- 所有非 200 状态均保守处理为 UNKNOWN，没有仅凭 HTTP 错误码证明“未执行”。
- `COMPLETE_PROTOCOL` 只表示终止、usage、DONE 和 HTTP 流结束均有效；结果状态仍 PENDING。
- 当前 adapter 计数后丢弃文本，不提供结果 artifact；物理 spool、空间预留兑现、durable handoff ACK、清理及买家交付属于后续阶段。
- 新增可选字段保持 None 时不进入旧 snapshot/event 编码，因此能读取阶段一 journal；不承诺旧二进制能读新增阶段二动作。
- 未实现或改动 auction、VCG、资金状态、收费和 settlement。
