## 性能校准

所有数值均为上述合成请求、三轮样本的平均值。吞吐是包含传输、控制探针和本地持久化的 runner 区间输出 tokens/s；原生指标另列。

| 最大在途 | 输出 tokens/s | 客户端 dispatch → 首 token | 原生 TTFT 均值 | 首事件队列/spool/journal | gate 后容量等待 | 容量满足 → 派发 | 采样原生 running 峰值 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 28.1 | 2032.6 ms | 200.2 ms | 20.4 ms | 7730.4 ms | 15.6 ms | 1 |
| 2 | 40.1 | 2004.6 ms | 211.3 ms | 19.9 ms | 3654.0 ms | 33.0 ms | 2 |
| 4 | 51.7 | 2072.1 ms | 217.9 ms | 20.0 ms | 0 ms | 14.1 ms | 3 |

全部轮次原生 preemption 增量为 0。采样 KV 使用峰值分别约 0.69% / 0.78% / 1.12%，包括仍留在引擎中的 prefix cache；它不是 scheduler 的物理 KV 预留证明。

在本次样本中，4 在途吞吐最高，约为 1 在途的 1.84 倍。这里只给出可复现的试验结果，尚未建立生产默认或 SLA。配置边界为 prompt≤8192、output≤512、context 计账≤32768、logical spool 16 MiB、physical spool 32 MiB；本轮实际 prompt=1737，**未对 8192 输入或完整 32K aggregate context 做压力校准**。相同输入在同一 namespace 的复用是本测试负载的一部分。

客户端时间包含 HTTPS、网关、网络、reader、同步和 journal；原生 TTFT 也不等于 GPU kernel 时间。首 token 不是精确 prefill-complete 时刻。Gate 后间隔把容量等待单列，首事件的持久化时间另列；commit 时间来自单写入者提交完成，避免把 worker ACK 调度延迟算作 commit。

## 真实断流与隔离恢复

旧 epoch 为 `chutes-c4d77a45070543c0bc51e28d96e3b4e4`，旧实例为 `f051d987-5b33-4835-8ff9-2d1497cf9372`。A 的首个生成进度已进入 durable journal 后关闭原连接：A 保持 UNKNOWN、原 in-flight/context/spool 预算继续保留；B 仍为原 next-unsent，没有 POST。

随后永久 seal 旧 admission，原生 running / waiting 连续三次为 0。Chutes SDK 仍保留 A 的前端 active bookkeeping，证据如实记录；没有将其宣称为干净的 stream closure。通过 owner API 暂停这个私有单实例 Chute，核对旧实例移除后重新启用；不会调用 miner-only 的实例删除接口。

2026-11-03 00:23:12 UTC 确认仅有新实例 `9a2019a4-b4e9-4c3e-b90f-946e27168846`，新 epoch 为 `chutes-91600c0b529045f8a753407c21e8a858`。profile 探针前后为同一唯一实例，旧实例缺席，完整 profile 不变。随后记录旧 epoch fence、清理 A 的不可恢复结果，**仅执行原 B**；B 的 8-token 结果同步到独立 sink，再 ACK 并清理。

最终 journal 中 A、B 各只有一个 intent；A 无重发，且不出现在新引擎 trace 中。最终 in-flight、context、logical/physical spool、owner 配额均为 0，snapshot 与 replay 一致。最终独立审计重建了全部 40 个完整结果的 spool 摘要，并核对隔离证据摘要确实进入原 epoch fence。

本次替换过程中平台一度注册了两个 pending 实例，尽管声明 `max_instances=1`。自动恢复在它们 active 前暂停，并加强为“所有实例恰好一个，profile 探针前后为同一唯一实例 ID”才接受证据；新增回归测试。心跳/账单字段刷新不误判为换实例，额外 pending 仍拒绝激活。已完成隔离之后只恢复只读等待，不重复暂停/启用操作。平台最终清理额外登记后才执行 B。

管理平台确认删除与本程序记录的 seal/idle 依赖 Chutes 管理面和调用通道可信；本次没有验证 TEE quote、硬件关闭证明、状态反回滚或 GPU exactly-once。
