## 验收场景与证据

测试位于 [tests/phase1.rs](../../tests/phase1.rs)。

| 需求 | 已验收内容 |
| --- | --- |
| 契约与授权 | 字节上限、未知/金融字段拒绝；错误签名、issuer、target、profile、摘要、成员数、重复 rank、重复 grant/execution 和非法 token 等不能产生派发。 |
| 完整登记 | 无效的后一成员导致整份计划不登记；排队请求/字节/乱序计划超限原子拒绝。 |
| 顺序与幂等 | 高序号计划先到时等 genesis；重复计划不产生事件或意图；ID/序号/前驱冲突持久化停派，不能用普通 activate 清除。 |
| 跨计划门控 | 前一请求的持久化进度或终止事件严格位于后一个派发意图之前；跨计划同样成立。 |
| 首进度与终止 | 空 token 进度无效；零可见输出可正常终止；同批首 token + terminal 单次原子记录；重复 token 内容不被误去重。 |
| 观察幂等 | 同 source sequence 同内容幂等；同 sequence 不同内容触发完整性故障；错误 epoch、跳号和未派发请求证据拒绝。 |
| 在途背压 | 请求数、context、总 spool 和逐 owner spool 逻辑预算有效；不越过队首去执行更短的后续请求。 |
| UNKNOWN | 保留门控事实、执行身份和容量；停止派发/新登记；可信终止解决执行责任后仍需要显式恢复。 |
| 原子性 | SQLite metadata-update 故障注入会回滚同事务的 journal INSERT；不返回意图、不发布内存状态；handle 进入 poisoned。 |
| 进度落盘失败 | 未提交的进度不会开门；重开后前一请求 UNKNOWN、后一请求 UNSENT。 |
| 重启恢复 | 重开默认 RECOVERY_REQUIRED；既有意图不重发；旧 epoch 核对隔离后，才能以新 epoch 执行后续未派发请求。 |
| 迟到事件 | fenced epoch 的证据只追加，不改写关闭事实或重复释放容量。 |
| 单写入者 | 同进程第二 handle、另一个进程和 symlink 别名均被锁拒绝；Unix 数据库权限为 0600。 |
| 重放与损坏 | 稳定分页和事件 ID；动作、事件投影、snapshot 或序号损坏被拒绝；snapshot 与独立重放一致。 |
| 状态组合 | 三份计划的全部 6 种到达排列 × 1/2/3 在途上限，均保持同一六请求派发顺序。 |
| 最小披露 | 外部事件无 prompt/output token IDs、签名、授权秘密或财务字段；原执行身份和摘要仍可关联。 |

## 固定 fixture 运行结果

派发意图顺序：

```text
exec-1-1 → exec-1-2 → exec-2-1
```

登记时 plan 2 先到，无法越过 plan 1。A 首进度前 B 被阻塞；A 尚未终止时 B 取得意图。B 先结束，随后 C 取得意图；A 后结束。这里的“同时在途”是状态机允许的并发，不是已经测到 GPU 并发。

最终结果：14 个事件；已连续登记到 plan 2；next cursor 为 `(3, 1)`；在途和 context 预算均为 0；snapshot 与独立 replay 一致。重开先停派，再显式启用第二 epoch；没有生成第四个推理意图。

逻辑 spool 预留仍为 1152 字节，符合阶段一边界：终止释放执行预算，不假装完成结果持久化与交接，也不提前清除结果空间责任。

## 已验收边界与后续阶段

- 阶段一没有 HTTP/SSE parser、上游网络提交、物理 spool 或 durable result handoff；这些不能由上述通过结果推断已完成。
- 授权与 profile 是候选集成契约。未改动或验收真实 BitRouter API、签名密钥体系、auction 或 settlement。
- 运维证据由可信调用者提供；核心记录和校验状态前置条件，不验证机器是否真的被隔离、配置是否已完成 GPU 校准或 TEE freshness。
- SHA-256 action chain 与 snapshot 校验检测损坏和不一致，不提供完整防回滚/防 fork 能力。OS writer lock 是合作式本地锁。
- 无实时 GPU 吞吐/延迟结论、无完整 TEE 部署验收、无真实推理 exactly-once 宣称。

下一阶段是接 mock vLLM/SSE，验证真实字节流解析与 transport 错误到上述 typed observations 的映射。Adapter 必须处理核心返回的错误，不能忽略无效观察后继续派发；对于已提交请求的协议/断流错误，应记录 UNKNOWN。
